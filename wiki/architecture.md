# Архитектура

Обновлено: 2026-11-11.

## Приложение

- `Front-end/app` — React UI.
- `Back-end` — FastAPI, API виджетов и модели PostgreSQL.
- В Compose `migrate` запускает миграции и выдачу прав до старта API. API использует runtime-роль `kpi_app`; миграции — отдельную роль `kpi_migrator`.
- PostgreSQL не публикует порт на хост. К ней обращаются API и миграционный контейнер во внутренней сети Compose.
- API доступен на `127.0.0.1:8000`, UI — на `127.0.0.1:5173`.

## Сохранение цвета серии

Цвет хранится отдельно на связи виджета с серией и возвращается из API. `null` означает стандартное автоматическое окрашивание. Миграция `0006_widget_series_colors` добавляет столбец цвета; локальный Compose прогоняет миграции перед API.

## Сетка виджетов

API и БД хранят `gridX`, `gridY`, ширину и высоту. Frontend-модуль `Front-end/app/src/domain/kpiLayout.ts` вычисляет свободные места, нормализует старые пересекающиеся позиции и упаковывает переставленные карточки. `KpiPage` управляет pointer-сессией, предпросмотром, анимацией и сохранением. Миграция для перетаскивания не требуется: координатные поля уже входят в контракт API.

На широком экране используется 12-колоночная сетка. На узком экране карточки складываются в одну колонку, сохраняя координаты широкого экрана. Полная модель поведения записана в [спецификации](../docs/superpowers/specs/2026-11-10-responsive-kpi-widget-grid-design.md).

## Compose и постоянство данных

Compose-проект закрепляет PostgreSQL volume с явным именем `kpi-dashboards-local-data`. Для PostgreSQL 18 данные монтируются в `/var/lib/postgresql`. API и UI перезапускаются автоматически, PostgreSQL остаётся доступной только внутри контейнерной сети, а миграции завершаются до запуска API.

Подробные команды и правила сохранения данных находятся в [локальном запуске](local-development.md).
