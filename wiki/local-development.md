# Локальная разработка

Обновлено: 2026-11-11.

## Один раз настроить

1. Установить Docker runtime для macOS и Compose. В текущей среде используется Colima.
2. В корне проекта создать локальный `.env` из `.env.example`, а `Back-end/.env` — из `Back-end/.env.example`.
3. Установить отдельные случайные значения для паролей PostgreSQL, миграционной и runtime-ролей. В `Back-end/.env` задать dev-вход `KPI_DEV_AUTH_EMAIL` и `KPI_DEV_AUTH_PASSWORD`.
4. Хранить настоящие значения только в локальных `.env`; не добавлять их в Git и Wiki.

Локальные файлы `.env` в текущем рабочем дереве уже созданы. Wiki не содержит их значений.

При продолжении сначала посмотреть `docker-compose ps`; если сервисы остановлены, выполнить обычный запуск выше.

## Запуск всего стека

После перезапуска Mac сначала запустить Colima, затем из корня проекта выполнить:

```sh
colima start
docker-compose up --build -d
```

Compose поднимает PostgreSQL, выполняет миграции, запускает FastAPI и после проверки API запускает UI. Открыть <http://127.0.0.1:5173>. Проверка API: <http://127.0.0.1:8000/healthz>.

Войти с локальной dev-учётной записью из `Back-end/.env`. Она предназначена только для локальной разработки; фактические логин и пароль не записывать в Wiki.

## Остановить и запустить повторно

Обычная остановка:

```sh
docker-compose down
```

Она сохраняет volume `kpi-dashboards-local-data`. При следующем `docker-compose up --build -d` используется та же локальная база с теми же тестовыми данными.

Не выполнять `docker-compose down -v`: эта команда удалит постоянный volume и все данные новой локальной БД. Не менять volume и не подключать прежнюю/исходную базу без явного запроса.

## Диагностика

```sh
docker-compose ps
docker-compose logs --tail=100 db migrate api frontend
curl http://127.0.0.1:8000/healthz
```

Если API не запускается, сначала проверить `migrate` и `db` в статусе Compose, затем журналы. Не запускать миграции против прежней базы. Compose-БД начиналась пустой; сейчас в ней уже есть локальный дашборд `First` с двумя виджетами. Данные прежних дашбордов не импортировались.

## Безопасность данных

Изменения в этой конфигурации затрагивают только новую локальную Compose-базу. Предыдущая база не удалялась и к стеку не подключена. Дашборды из неё не импортированы. Не очищать volume и не переносить данные без отдельного решения о резервной копии и источнике.
